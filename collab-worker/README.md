# CHECKform shared glossary

The 821 base terms come from `src/glossary-data.js`, generated from the workbook on the CHECKform site. D1 stores only shared changes, three member code hashes, and every revision with its author. The CHECKform website is the editing interface; the Chrome extension reads published changes for Crowdin checks. Crowdin source and translation text never reach this Worker.

## Current deployment

- Worker: `https://checkform-glossary.nzs2593.workers.dev`
- D1: `checkform-glossary`
- Public read: `GET /v1/glossary` (same visibility as the existing public GitHub Pages glossary)
- Authenticated edit: `POST /v1/changes`, bearer personal code

The D1 schema is in `schema.sql`. `CODE_PEPPER` is a Cloudflare Worker secret. Personal codes and pepper are generated by `scripts/create-collab-access.mjs` into a directory outside the repository. Never commit those files. Each code is assigned to one member: `zakharov.n`, `sitnikova.r`, `zyryanova.k`.

To disable a member, set `active = 0` for that member in D1. To rotate one code, generate a new code and hash with the existing pepper, update that member's hash in D1, and send the new code privately. A new pepper would invalidate all member codes.

Every accepted edit creates a new immutable `revisions` row. To inspect history, query `SELECT version, actor_id, changed_at, change_json FROM revisions ORDER BY version DESC`. To roll back a term, publish a new change that restores the prior value; do not delete revision rows.

The public site and extension read `data/collaboration-config.json` to locate the Worker. The extension's manifest must include the Worker's exact host in `host_permissions`. The Chrome Web Store privacy disclosure must include the personal code and glossary edit data flow before uploading a new package.
