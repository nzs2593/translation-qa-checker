# Согласование изменений глоссария

CHECKform на GitHub Pages остаётся статической страницей. Предложения создаются как GitHub Issues; владелец утверждает их через отдельный Cloudflare Worker. Код согласования и токен GitHub хранятся только в секретах Worker. Worker требует Cloudflare Access и точный email владельца.

## Включение

1. Создайте Cloudflare Worker из `approval-worker/index.js` и защитите **весь Worker** через Cloudflare Access. Разрешите вход только вашему email. Пока Access не подключён, код отказывает всем запросам.
2. Создайте GitHub fine-grained token только для `nzs2593/translation-qa-checker`: Contents (read/write) и Issues (read/write). Добавьте его как секрет Worker `GITHUB_TOKEN`.
3. Добавьте секрет Worker `APPROVAL_CODE` с вашим кодом; не записывайте его в репозиторий, конфигурацию сайта или GitHub Issue. Добавьте `ADMIN_EMAIL` с email, который Access возвращает после вашего входа.
4. Создайте namespace Workers KV, подключите к Worker с именем binding `ATTEMPTS`. Он ограничивает ввод кода пятью попытками в час для аккаунта владельца.
5. После проверки Access и тестового предложения укажите URL Worker в `data/collaboration-config.json` как `approvalApi` и опубликуйте коммит. До этого кнопка согласования на сайте остаётся недоступной.

На сайте владелец открывает «Предложения по словарю» → «Согласовать по коду». В защищённой вкладке видны старый и новый варианты, дополнительный корень и поле кода. После утверждения Worker обновляет `data/shared-glossary.json` и закрывает GitHub Issue. Сайт при открытии читает новый JSON, расширение проверяет его каждые пять минут и хранит последнюю загруженную копию. Тексты переводов в Worker не отправляются.

Предложения через Issues публичны, поскольку репозиторий публичный. Не вставляйте в предложение рабочие тексты или персональные данные. Для закрытого потока предложений понадобится отдельный защищённый приём заявок.
